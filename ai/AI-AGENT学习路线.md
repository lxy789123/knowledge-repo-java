# AI‑AGENT 学习路线

> 参考来源：【AI】Agent 全栈进阶｜系统化学习路线专题‑阿里云开发者社区 原文链接：https://developer.aliyun.com/article/1754230#1_43

## 一、大模型基础与会话调用

**概念阐明** Agent 本质是基于大模型 API 构建的应用系统。大模型会话调用是 Agent 开发的底层底座，所有 Agent 的思考、推理、交互都建立在大模型 API 请求‑响应能力之上。本模块主要掌握如何和大模型服务建立通信、处理返回数据、管理多轮对话上下文，为上层 Agent 逻辑打下基础。

**知识点**

#### 1.LLM‑API 调用

##### 1.1 流式输出

- 概念：流式输出（stream）基于 SSE 服务端推送协议，模型不会等待全部 token 生成完毕再返回，而是分段返回结果。
- 核心知识点：SSE 协议基础、流式 chunk 数据拼接、中断处理、流式与非流式返回报文差异；Agent 中实时展示 Thought 思考过程。

##### 1.2 多模态输入

- 概念：大模型不仅接收文本，还可以接收图片等非文本输入，让模型具备感知图片信息的能力。
- 核心知识点：图片 URL/Base64 编码入参方式、多模态模型 API 参数配置；在 Agent 场景下完成识图、解析截图、解析图表。

#### 2. 提示词工程

- 概念：提示词工程是通过指令、角色设定、示例引导大模型输出预期行为，是低成本约束模型行为的手段。
- 核心知识点：角色 Prompt、Few‑shot 示例、CoT 思维链；Prompt 边界约束；提示词的局限性，不能单独生产可靠 Agent。

#### 3. 对话历史管理

- 概念：对话历史保存每一轮用户、模型、工具的消息，构成 Agent 的上下文，大模型依靠对话历史理解多轮任务。
- 核心知识点：消息结构体 role/user/assistant/tool；token 窗口上限；消息组装逻辑；上下文溢出带来的截断问题。

**本章学习计划（建议 5‑7 天）**

1. 第 1‑2 天：调用大模型 API，完成普通非流式、流式输出 demo，实现客户端逐块打印返回内容；
2. 第 3 天：调试多模态接口，传入图片完成识图问答；
3. 第 4‑5 天：练习提示词工程，使用 CoT、Few‑shot 完成推理类任务；
4. 第 6‑7 天：实现对话历史的简单内存管理，观察 token 超限截断现象；整理笔记，完成小 demo，输出简单聊天程序。

## 二、工具调用与结构化输出

**概念阐明** 普通大模型只能输出文本；Agent 通过工具调用，让模型可以 “决定调用外部能力”，真正执行现实世界动作。Function Calling + JSON‑Schema 约束，用来解决模型输出自由文本不可解析的痛点，实现模型思考到外部函数执行的闭环。

**知识点**

#### 1.Function Calling 原理

- 概念：Function Calling 是大模型的能力，模型根据用户问题判断是否调用工具，输出工具名与参数；**模型本身不会执行函数，执行逻辑由业务代码完成**。
- 核心知识点：完整调用链路：用户提问→传入工具描述→模型输出工具调用→业务代码执行函数→工具结果回传给模型→模型生成最终回答。

#### 2.Tool 工具的定义与注册

- 概念：Tool 是 Agent 可调用的外部能力，例如查询时间、查询文件、网络搜索；工具描述使用 JSON‑Schema 表达，代码维护工具注册表完成映射。
- 核心知识点：工具描述字段编写规范；工具注册表实现；工具数量过多带来的误选择问题；工具入参必填项、类型定义。

#### 3.JSON‑Schema 约束输出

- 概念：JSON‑Schema 用来强制规定输出 JSON 字段、类型、是否必填，解决大模型输出格式混乱、markdown 包裹、输出注释等解析失败问题。
- 核心知识点：两种使用方式：Function Calling 内置 schema、Prompt 内强制 schema；输出结果校验、异常捕获、容错处理。

#### 4. 最小化工具调用循环

- 概念：工具调用循环指模型多次调用工具的往复流程；最小化即尽可能减少无效工具轮次，避免资源浪费和死循环。
- 核心知识点：工具循环完整流程；最大循环次数限制；优化手段：优化工具描述、Few‑shot 示例；识别无效重复调用。

**本章学习计划（建议 7‑10 天）**

1. 第 1‑3 天：吃透 Function Calling 完整原理，编写简单工具（获取当前时间、计算器），实现完整调用链路 demo；
2. 第 4‑5 天：学习 JSON‑Schema 语法，练习编写工具参数 schema，增加返回格式校验逻辑；
3. 第 6‑8 天：实现工具注册中心代码，完成多工具选择调用；
4. 第 9‑10 天：实现工具调用循环，设置最大轮次限制，观察无效循环现象，做边界测试；输出可运行的多工具调用 Demo。

## 三、RAG 检索增强生成

**概念阐明** 大模型训练数据存在时间、私有知识限制，无法直接掌握企业内部文档。RAG（检索增强生成）不修改模型权重，在生成答案前从私有知识库检索相关片段作为上下文输入模型，降低幻觉，给 Agent 提供私有领域知识获取能力。

**知识点**

#### 1.RAG 核心流程：增强、检索、生成

- 概念：增强 = 文档预处理构建索引；检索 = 根据问题召回相关片段；生成 = 把检索片段 + 用户问题送入大模型得到答案。
- 核心知识点：RAG 完整三阶段链路；Agent 场景下将 RAG 封装成 Tool，需要知识时主动调用检索。

#### 2. 向量数据库与 Embedding 模型

- 概念：Embedding 模型将文本转为语义向量；向量数据库专门存储向量，提供相似度检索。
- 核心知识点：开源 / API Embedding 选型；向量数据库 FAISS、Chroma、Milvus 基础使用；向量维度必须匹配。

#### 3. 文档解析与索引构建

- 概念：原始文档经过解析、清洗、分块、向量化，存入向量库形成可检索索引。
- 核心知识点：PDF/Markdown 文档加载解析；chunk 分块大小、重叠 overlap 调优；分块过大过小带来的召回缺陷。

**本章学习计划（建议 8‑12 天）**

1. 第 1‑3 天：学习 Embedding，完成文本向量化，使用 Chroma/FAISS 做基础相似度检索 demo；
2. 第 4‑7 天：实现文档解析、文本分块，构建本地知识库索引；
3. 第 8‑10 天：实现完整 RAG 问答链路，测试不同分块参数对回答效果的影响；
4. 第 11‑12 天：把 RAG 封装成一个 Tool，接入上一章工具调用 demo，让 Agent 自主检索知识库。

## 四、Agent 设计模式

**概念阐明** Agent 设计模式是一套标准化推理行动框架，规定 Agent 如何思考、如何拆解任务、如何行动、如何纠错。不同模式适配不同复杂度任务，是构建智能 Agent 的顶层逻辑。

**知识点**

#### 1.ReAct 模式: Thought‑Action‑Observation 循环

- 概念：ReAct=Reason+Act，思考‑行动‑观测循环；Agent 先思考，选择工具执行，拿到观测结果，循环直到任务完成。
- 核心知识点：Thought 思考、Action 动作、Observation 观测三要素；适合开放式多轮工具任务。

#### 2.Plan‑and‑Execute 模式：先规划后执行

- 概念：分为规划阶段、执行阶段；模型先把复杂任务拆解子任务清单，再逐个执行子任务。
- 核心知识点：规划阶段的任务拆解；规划错误带来连锁失败；适合长链路复杂任务。

#### 3.Reflection 模式：自我反思与修正

- 概念：Reflection 即自我反思；Agent 执行完一轮任务，复盘执行过程，识别错误、信息缺失，修正策略重新执行。
- 核心知识点：反思 Prompt 编写；反思带来 token 消耗增加；用于提升复杂任务准确率。

**本章学习计划（建议 7‑10 天）**

1. 第 1‑4 天：基于前面工具调用代码实现 ReAct 模式 Demo，跑通 Thought‑Action‑Observation 完整循环；
2. 第 5‑7 天：实现 Plan‑and‑Execute，增加任务拆解逻辑，测试规划出错场景；
3. 第 8‑10 天：增加 Reflection 反思模块，对比开启反思前后任务完成效果；对比三种模式的适用场景，整理优缺点笔记。

## 五、Agent 记忆机制

**概念阐明** 普通对话上下文会话结束就丢失；记忆机制让 Agent 拥有跨轮次、跨会话的经验留存能力。分为短期记忆（当前会话）、长期记忆（持久化存储），解决长对话上下文超限、跨会话记住经验的问题。

**知识点**

#### 1. 短期记忆与长期记忆

- 概念：短期记忆保存在当前会话上下文窗口，受 token 限制；长期记忆持久化存储，跨会话可以复用。
- 核心知识点：两者存储位置、生命周期；短期记忆就是对话消息列表；长期记忆存储介质：向量库、关系数据库。

#### 2. 上下文管理策略（滑动窗口、摘要压缩）

- 概念：当对话不断变长，上下文会超出模型 token 上限，需要做记忆裁剪。
- 核心知识点：滑动窗口（保留最近 N 条消息）；摘要压缩（将历史对话压缩为简短摘要）；两种策略各自优缺点。

#### 3. 基于向量数据库的记忆存储与召回

- 概念：把 Agent 关键经验、用户信息、任务结果向量化存入向量库；新任务执行时召回相关历史记忆作为输入。
- 核心知识点：记忆写入时机；记忆召回逻辑；记忆过滤，避免无关记忆干扰当前任务。

**本章学习计划（建议 6‑8 天）**

1. 第 1‑2 天：区分短期 / 长期记忆概念，实现滑动窗口上下文裁剪；
2. 第 3‑5 天：实现摘要压缩，对比滑动窗口与摘要压缩的效果差异；
3. 第 6‑8 天：基于向量库实现长期记忆写入与召回，接入 ReAct Agent，让 Agent 能够复用历史任务经验。

## 六、工程化与兜底

**概念阐明** Demo 环境 Agent 效果尚可，上线生产环境会大量出现异常。本模块聚焦生产落地，处理 Agent 各类故障，建立可观测、评估体系，保证 Agent 稳定性。

**知识点**

#### 1.Agent 常见故障：死循环、幻觉、误调用

- 概念：Agent 运行中高频出现的三类典型问题；死循环即无限工具调用；幻觉即编造事实；误调用即选错工具、参数错误。
- 核心知识点：死循环的上限轮次兜底；幻觉的缓解手段（RAG、反思、事实校验）；误调用处理：参数校验、异常捕获、工具描述优化。

#### 2. 可观测性与评估（Eval）

- 概念：可观测性是完整记录 Agent 每一轮运行链路，方便排查问题；Eval 评估是自动化测试 Agent 任务完成质量。
- 核心知识点：日志埋点要素：prompt、入参、工具调用、返回结果、token 消耗；构建测试集；评估指标：任务成功率、幻觉率、工具调用正确率。

**本章学习计划（建议 5‑7 天）**

1. 第 1‑3 天：梳理 Agent 故障场景，给前面 Agent 代码增加异常捕获、最大循环限制、参数校验；
2. 第 4‑5 天：实现 Agent 全链路日志埋点，记录每一步运行信息；
3. 第 6‑7 天：搭建简易 Eval 测试集，批量测试 Agent 任务效果，统计任务成功率；总结生产环境落地风险清单。

> 整体学习周期参考：全套学习建议 38‑54 天，可以根据个人基础加快或拉长。
